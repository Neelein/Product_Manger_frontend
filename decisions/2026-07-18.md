# Decision Log — 2026-07-18

## Inventory System Frontend

Added inventory management UI with search, list, detail, and items CRUD.

## Key Decisions

1. **InventoryListPage** (`/inventory`): search bar + inventory list table. Public read access.

2. **InventoryDetailPage** (`/inventory/:id`): top section shows/edits inventory summary, bottom section shows/edits items.

3. **ProductDetail** integration: each price-item shows inventory summary line + "管理庫存" link.

4. **Navbar**: add "庫存管理" link to navbar-nav, visible to all.

5. **API convention**: follow backend POST-based convention for mutations.

6. **Status labels**: use Chinese labels matching backend (銷售中/完售/註銷 for inventories, 可用/出售/註銷 for items).

## Back-to-Product Navigation on Inventory Detail

Added `product_id` to the backend Inventory domain model (SQL functions, Go struct, scan), frontend type, and a "← 返回產品" link on InventoryDetailPage routing to `/products/{product_id}`.

## Key Decisions

1. **Backend `product_id`**: computed via JOIN in all 3 PostgreSQL functions (`get_inventory_by_id`, `get_inventory_by_price_id`, `list_inventories`) rather than stored denormalized — avoids data inconsistency.

2. **Frontend navigation**: placed alongside the existing "← 返回庫存列表" link with the same `.back-link` styling, visible to all users regardless of auth.

## Move "返回產品" Into detail-header (2026-07-18)

Moved the "← 返回產品" link from `page-header` into `detail-card > detail-header` for visual grouping with the inventory name and status.

**Rationale**: keeps the back-to-product action visually attached to the inventory card content rather than the page-level toolbar, making the relationship clearer.

## Add `product_detail_id` to Frontend Inventory Type (2026-07-18)

Added `product_detail_id: string` to frontend `Inventory` interface to match the updated backend `Inventory` struct.

**Rationale**: the backend `Inventory` struct now includes `product_detail_id` in its JSON responses. The frontend type must match to avoid type errors and to make the field accessible for future use.
