# Add confirm-password field to registration (2026-08-07)

## What
Added a「確認密碼」(confirm password) field to the frontend registration form and client-side validation that the two entered passwords match, before the form is submitted.

## Why
The user requested that registration require a confirm-password field that must equal the original password, to reduce typos at signup.

## Changes
- `src/pages/LoginPage.tsx`:
  - New `confirmPassword` state, reset in `resetForm()` and cleared after successful registration.
  - New「確認密碼」password input shown only in register mode, with `autoComplete="new-password"`.
  - `validate()` rejects when confirm is empty (`請輸入確認密碼`) or does not equal `password` (`兩次輸入的密碼不一致`). Both checks are guarded by `mode === 'register'` so login is unaffected.
  - Also added `autoComplete="new-password"` to the primary password input to avoid browser autofill.
- `e2e/helpers.ts`: `fillRegisterForm` now fills the confirm field and uses `getByLabel('密碼', { exact: true })` since「密碼」is now substring-ambiguous with「確認密碼」.
- `e2e/registration-code.spec.ts`: invalid-code test fills confirm (and uses `{ exact: true }`) so validation passes and the backend rejection is still asserted.
- `e2e/auth.spec.ts`: added a test asserting a mismatched confirm password shows `兩次輸入的密碼不一致` and stays on the registration form.

## Notes
Confirm-password is a client-side UX guard; the backend still receives a single `password` and is unchanged.

## Verification
`npm run lint` exit 0; `npm run build` success; `npm run e2e` (13 specs) all green.
