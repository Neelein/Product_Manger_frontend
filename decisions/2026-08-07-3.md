# Harden AuthContext session bootstrap against racing 401s (2026-08-07)

## What
Make `AuthProvider`'s one-time `GET /api/members/me` bootstrap robust to (a) React `StrictMode` double-running the mount effect in dev, and (b) a 401 from one concurrent request nulling out a valid authenticated session. Defense-in-depth on top of the backend fix that removed per-request session rotation.

## Why
The frontend E2E suite flaked in CI. Root cause (confirmed via a Playwright network trace): the CI backend (checked out from backend repo `main`, which still rotated the session key on every authenticated request) received two concurrent `/me` requests carrying the same cookie. The first rotated the key and deleted the old one; the second returned `401`, and AuthProvider's `.catch(() => setMember(null))` then wiped the valid session. All member-gated UI (create buttons/links, navbar name) disappeared, protected routes redirected to `/login`, and the E2E specs timed out or failed on `element was detached from the DOM`.

The backend rotation removal (merged to `main`) is the root fix; this frontend change keeps the login state robust even if a backend rotates sessions or a page fires concurrent authenticated requests.

## Changes
- `src/context/AuthContext.tsx`: added a module-scope `getSessionOnce()` that deduplicates the in-flight `getCurrentMember()` call (`sessionRequest ??=`), so duplicate/concurrent mounts share one real request. The bootstrap `useEffect` now uses `getSessionOnce()` and its `.catch` no longer clears `member` (member starts `null` and is only cleared by `logout()`), preventing a racing `401` from overwriting a valid session.

## Verification
`npx tsc -b` passes; `npm run lint` passes; `npm run e2e` (Playwright, 9 specs) passes green.
