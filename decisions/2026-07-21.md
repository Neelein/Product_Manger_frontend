# Decision Log — 2026-07-21

## Private Message Room List

Added private message room listing UI leveraging the backend chat API.

## Key Decisions

1. **ChatRoomListPage** (`/chat/rooms`): card list layout matching AnnouncementListPage. Requires auth (protected route).

2. **Card content**: each card shows room name (聊天主題) and created_at (創建時間). Creator name is skipped because the backend API returns `created_by` as UUID only.

3. **Reuse announcement CSS**: the `.announcement-list-page`, `.announcement-card`, etc. styles are reused directly for the chat room list.

4. **API convention**: follows `GET /api/chat/rooms` returning `{ rooms: [...] }`. All chat endpoints require auth.

5. **StrictMode fix**: `useChatRooms` hook uses an `active` flag with `useEffect` cleanup.

## Chat Room Create Page

Added a form page to create chat rooms.

## Key Decisions

1. **ChatRoomCreatePage** (`/chat/rooms/new`): simple form with name + type fields. No member selection (member_ids sent as empty array).

2. **Member selection deferred**: member selection will be added later via a separate "add members" UI after a member list API is created on the backend.

3. **Form reuse**: uses existing `.form-card`, `.form-group`, `.btn-primary` etc. styles from the announcement form.

4. **Route protection**: wrapped in `ProtectedRoute` (requires auth).

5. **Redirect on success**: after creation, navigates back to `/chat/rooms`.
